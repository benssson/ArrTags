# ADR-029: Identity-Anchored Reconciliation Cursor (Amendment to ADR-022 Clause 3)

**Status:** Accepted (v1.2). This amends **only ADR-022 clause 3**. ADR-022's
clauses 1, 2, 4, 5, 6, and 7 — its persisted record shape, `Cache` authority,
scope-reset rule, trigger exclusion, and per-run bounds — are unchanged, and no
ADR-022 text is rewritten.

**Date:** 2026-09-28

### Context

ADR-022 (Successive-Run Reconciliation Coverage) established a persisted,
bounded `(SortName, itemId)` reconciliation cursor. Its clause 3 states that the
enumerator orders candidates by `SortName` ascending with the item id ascending
as a unique tie-break (a total order) and gains a resume capability that returns
the page strictly after a supplied key, implemented by "a query predicate where
the host query supports one, or a bounded linear skip at run start".

Verification against the pinned Jellyfin 12.0.0 host refutes two of clause 3's
premises (`docs/research/jellyfin-expert/reconciliation-cursor-host-order.json`,
findings F1-F10):

- The pinned host applies **`SortName` ASC, `Name` ASC** to the ArrTags candidate
  query, where `Name` is the raw item name and is neither unique nor an
  identifier. No supported `OrderBy`/`ItemSortBy` configuration yields an
  identifier tie-break, so no supported host order is identifier-stable.
- No supported query surface expresses a "strictly after key" / keyset / seek
  predicate. The only order-relative controls are `StartIndex`/`Limit` offset
  paging (translated by the host to SQL `LIMIT`/`OFFSET`), the `AdjacentTo`
  window (which materialises the whole ordered id set and is unbounded), and the
  by-name range filters (`NameStartsWithOrGreater`/`NameLessThan`, which compare
  the lower-cased `SortName` column only and are not a keyset cursor for
  `(SortName, Name)` or `(SortName, itemId)`).

Clause 3's total-order-plus-seek mechanism therefore cannot be realized as
written, while clause 3's "bounded linear skip at run start" branch is realizable.
The read-only architecture review
(`docs/reviews/architecture/adr-022-clause-3-conformance.json`) recommended the
minimal conformant correction recorded here, and the user approved it.

### Decision

The cursor remains the opaque, bounded `(SortName, itemId)` position defined by
ADR-022 clauses 3 through 5, with the following corrections, which leave the
persisted record shape, its `Cache` authority, the scope-reset rule, the trigger
exclusion, and the per-run bounds of clauses 1, 2, 4, 5, 6, and 7 unchanged.

1. **The host order.** The host does not order the candidate query by
   `(SortName, itemId)`. Its effective order is `SortName` ascending with the raw
   `Name` ascending as the tie-break. No supported configuration yields an
   identifier tie-break, and the `(SortName, Name)` order is not guaranteed to be
   a strict total order. ArrTags does not claim to impose a total order on the
   host's pages; it locates a known boundary item within the host's own order.

2. **The resume mechanism.** No host query predicate returns the page strictly
   after a supplied key. The only realizable resume is the bounded linear skip at
   run start: the enumerator gains a resume capability that walks the
   host-ordered pages from the start of the order until it locates the record's
   boundary item, then returns the page strictly after it. The unsupported
   query-predicate branch is **withdrawn** (the by-name range filters compare the
   `SortName` column only and are not a keyset cursor for `(SortName, Name)` or
   `(SortName, itemId)`).

3. **The key is an ArrTags-side identity anchor.** The record's
   `(SortName, itemId)` is an ArrTags-side anchor located by scanning the host
   order and matching the record's unique `itemId`; the `SortName` component is a
   boundary hint and diagnostic, not the ordering authority. Because the locate
   step matches the unique item id, an item added or removed before the cursor
   does not shift the resume point: an item added after the cursor is covered in
   the current cycle, and an item added before it is covered at the next wrap (or
   sooner after a scope reset). The locate scan walks the host order in bounded
   pages and checks cancellation between and inside pages, so clause 7's per-run
   bounds are preserved. The run's resume work is proportional to the boundary
   item's position in the host order (and the host enumerates server-wide movie
   and episode candidates), so one run is **bounded by the scope size plus
   `QueueCapacity`, not by a constant**; a full round-robin cycle performs
   cumulative skip work quadratic in the candidate count. This is accepted as the
   cost of the only host-supported mechanism.

4. **Reset on an unlocatable anchor.** If the boundary item cannot be located (it
   was removed or became ineligible, or the host order changed), the cursor
   resets to the start per clause 5 rather than failing the run; the mechanism
   does not rely on cross-version ordering stability.

5. **Tie caveat.** Coverage is guaranteed for rows strictly ordered by
   `(SortName, Name)` and is best-effort for rows that tie on that exact pair,
   which have no host-guaranteed relative order. A page boundary inside such a
   tie can re-cover, or in a persistently ordered tie skip, an item across a
   cycle; this is a registered residual limitation, not a covered case.

### Consequences

- The ADR-022 clause 3 conformance gap is corrected without rewriting ADR-022:
  the persisted bounded `(SortName, itemId)` `Cache` record, its scope-reset
  rule, the trigger exclusion, the enqueue-outcome vocabulary/cursor-advance
  rule (clauses 1-2), the storage contract (clause 4), the reset rule (clause 5),
  and the per-run bounds (clause 7) all stand.
- Whole-scope coverage across successive scheduled/post-scan runs is retained:
  items are located by identity, so add/remove before the cursor does not shift
  the resume point, and the cursor wraps at the end.
- The resume scan uses only the supported `ILibraryManager` query surface
  (`StartIndex`/`Limit`/`OrderBy`); a host ordering change degrades to a rescan or
  a reset-to-start, not a wrong result.
- No provider call, render, or image write is added.

**Registered residual limitations** (recorded, not covered cases):

1. Per-run resume is **O(offset)** ordered rows and a full cycle is
   **O(N²/`QueueCapacity`)** cumulative skip work; `N` is the **server-wide**
   movie+episode candidate count because the enumerator query is not
   library-scoped.
2. Rows tying on the exact `(SortName, Name)` pair have no host-guaranteed
   relative order, so a page boundary inside such a tie can re-cover or
   persistently skip an item across a cycle.
3. Removing or making ineligible the boundary anchor resets the cursor to the
   start, re-covering one cycle's prefix (a bounded but visible cost).
4. The host order is an internal implementation detail with no plugin
   compatibility promise; the mechanism degrades to a rescan/restart, not a wrong
   result, if it changes.

### Rejected alternatives

- **The host-query-predicate seek.** Withdrawn: no supported `after-key`/keyset
  predicate exists for `(SortName, itemId)` or even `(SortName, Name)`.
- **Coarse `SortName` range-filter seek** (`NameStartsWithOrGreater`/
  `NameLessThan`) **plus a bounded skip within the `SortName` group.** Not
  adopted: the filters compare the lower-cased `SortName` column only and are not
  a keyset for the exact cursor key; their collation relative to `ORDER BY` and
  their nullable-`SortName` behavior are unresolved, so correctness is not
  established. A separate `jellyfin-expert` verification would be required first.
- **Persist an integer offset plus the key, and re-seek.** Rejected: this is the
  integer-offset cursor ADR-022 already rejects; SQLite `OFFSET` is `O(offset)`
  regardless, so re-verification adds a full scan without a material gain.
- **Per-library (`ParentId`/`TopParentIds`-scoped) enumerator with one cursor per
  enabled library.** A possible future mitigation of the registered skip cost, but
  it changes the enumerator's server-wide query and clause 4's single fixed
  record into a per-scope set, so it is out of scope for this minimal amendment.
- **Client-side whole-scope materialisation then keyed paging.** Rejected:
  unbounded per-run memory and ordering work, contradicting clause 7 and the
  project's performance goals.
