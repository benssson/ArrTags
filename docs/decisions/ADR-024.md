# ADR-024: Empty-Selection Artwork Restoration

**Status:** Accepted (v1.2). This supersedes the empty-selection clause of ADR-009
and extends the restoration triggers of ADR-002/ADR-003.

**Date:** 2026-09-25

### Context

When the enabled selectors and their allowlists resolve no displayable value,
`BadgeDefinitionResolver.Resolve` returns an empty selection and the renderer
returns `PassThrough(NoDisplayableValue)`; the coordinator returns a
pass-through result before the publisher is invoked and performs no image
mutation. ADR-009 defines this pass-through as preserving the current usable
artwork. For an item ArrTags previously published, that current artwork is the
old ArrTags badge (with its old selector values, position, size, and palette),
and there is no restore or removal path for an empty selection: restoration runs
only on item removal or the lifecycle drain. The stale badge therefore persists
indefinitely, and each later reconciliation resolves the same empty selection,
passes through, and preserves it again. This is limitation F7 in
`docs/limitations/open.md`.

The pass-through behavior is deliberate for the other preservation reasons
(missing metadata, ineligible surface/match, unavailable source), where
preserving the current artwork is the correct fail-closed behavior.

The renderer emits `NoDisplayableValue` for two distinct conditions: an empty
resolved selection (the intended F7 case) and a **non-empty** selection whose
layout is empty because nothing fits the safe area at the scaled geometry (for
example a very large Extra Large size on a small poster, made more reachable by
ADR-027's factor 2.0). Keying the restore on the reason alone would therefore
remove or restore a correct badge when a valid value simply could not fit,
violating ADR-009's shorten/omit-preserve contract. This decision separates the
two conditions.

### Decision

An empty resolved selection on an item with an owned published ArrTags session is
a **restore obligation**, not a preserve.

1. **Discriminator.** The restore obligation applies only when the resolved
   `BadgeSelection` is empty. `RenderPassThroughReason.NoDisplayableValue` is
   narrowed to mean exactly that: the renderer adds a distinct bounded
   pass-through reason, `NoFittingBadge`, for a **non-empty** selection whose
   layout is empty (nothing fits the safe area after shorten/omit). Restoring or
   removing keys on `NoDisplayableValue` (now unambiguous), not on a layout
   failure.
2. **Restore/removal.** When the empty-selection pass-through applies and the
   item has an owned published ArrTags image (a live owned session), the
   coordinator drives the existing guarded restoration path instead of returning
   before it: if a retained source baseline exists, restore it; if the baseline
   was absent, remove the ArrTags image. The pass-through occurs in
   `ArtworkGenerationCoordinator`; the only restore entry point is the internal
   `ArtworkPublisher.RestoreAsync(jellyfinItemId, surface, fence,
   cancellationToken)`, which requires an `ArtworkLifecycleFence` and a
   `Published` state. The coordinator calls it under the current durable fence
   (`ArtworkLifecycleFence.Normal` during normal operation, which
   `ArtworkOperationFencing.AllowsNewRestoration` permits). No second restore
   path is introduced, and the per-subject gate and recovery suite are not
   bypassed.
3. **Crash recovery.** A Normal-fence restoration is intended and
   crash-recoverable: it is recorded as a durable `ArtworkOperation` and resumed
   on restart by `ArtworkRecoveryDecisions` through the ordinary recovery gate
   (`ArtworkReconciler`).
4. The restore/removal is performed through the existing crash-recoverable
   `ArtworkOperation` protocol (ADR-003); it does not bypass the durable
   write-ahead record, the recovery gate, or per-subject serialization.
5. The other pass-through reasons (`NoMetadata`, `NoFittingBadge`,
   `IneligibleSurface`, `MatchNotEligible`, `SourceUnavailable`) keep the ADR-009
   behavior unchanged: the current usable artwork is preserved and no image
   mutation occurs. In particular, a non-empty selection that cannot fit the safe
   area (`NoFittingBadge`) performs no mutation.
6. If the item is not an owned ArrTags session, an empty selection remains a
   pass-through; ArrTags never mutates artwork it does not own.
7. The outcome is a bounded generation result that records the restore/removal
   classification; it is not a render output change, so no `RenderVersion` or
   renderer-configuration schema advance is required.
8. This supersedes the ADR-009 clause "If `BadgeMetadata` is absent, the match is
   not eligible, no field is displayable, or the source is unavailable, the result
   is `PassThrough` and the current usable artwork is unchanged" **only for the
   owned-session empty-selection case**; the clause remains in force for the
   other cases. It extends the ADR-002/ADR-003 restoration trigger set beyond item
   removal and lifecycle drain.

### Consequences

- Narrowing a selector allowlist, or otherwise making an item's values
  non-displayable, removes or restores the previously published ArrTags badge
  instead of leaving a stale badge that no longer matches the configuration.
- A valid but un-fittable value (`NoFittingBadge`) still preserves the current
  artwork, so a layout failure never removes a correct badge.
- An output-policy change (global position or size) now takes effect through the
  empty-selection path because the stale image is no longer preserved.
- Restoration runs through the same guarded, recoverable protocol as removal, so
  the retained source baseline and ownership semantics are preserved.
- More restore/removal operations are created (one per newly-empty owned
  selection); the existing recovery gate, quota, and retention bounds apply.
- A new bounded `RenderPassThroughReason` member is added; it is not output
  fingerprint-affecting (a pass-through produces no artifact).

### Rejected alternatives

- **Preserve the stale badge (current behavior).** Rejected: it is the documented
  limitation and produces artwork that contradicts the configuration.
- **Key the restore on the `NoDisplayableValue` reason without splitting the
  conditions.** Rejected: the renderer emits the same reason for a non-empty
  selection that merely fails layout, so a correct badge would be removed on a
  layout failure.
- **Treat every pass-through as a restore.** Rejected: it would remove a correct
  badge on a transient provider outage or unavailable source, violating the
  fail-closed preserve-current-artwork guarantee.
- **Remove the image directly without the lifecycle protocol.** Rejected: it would
  bypass crash recovery, ownership, and provenance and is not supported.
