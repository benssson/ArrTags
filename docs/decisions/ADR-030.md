# ADR-030: Cancellation Is Not a Terminal Artwork-Mutation Outcome

**Status:** Accepted (v1.3). This amends the terminal-outcome set of ADR-003
(crash-recoverable artwork publication) and extends the restoration trigger set
recorded by ADR-024. It does not weaken ADR-002's fail-closed ownership rule or
ADR-003's mutation lower-bound rule.

**Date:** 2026-10-01

### Context

`ArtworkPublisher` guards every external image mutation with a `try`/`catch`
around the host call and, in the cancellation case, writes two records before
returning:

- `src/ArrTags/Artwork/ArtworkPublisher.cs:735-743` — the restoration mutation
  (`SaveImageAsync` / `RemoveImageAsync`)
- `src/ArrTags/Artwork/ArtworkPublisher.cs:380` — the publication image mutation
- `src/ArrTags/Artwork/ArtworkPublisher.cs:414` — the publication item update

Each advances the durable operation to `ArtworkOperationPhase.RecoveryBlocked` and
the published state to `ArtworkPublicationState.RestoreBlocked`, and the
restoration site then returns `ArtworkReconciliationOutcome.Cancelled`.

`ArtworkOperationPhases.IsTerminal` (`src/ArrTags/Artwork/ArtworkOperationPhases.cs:50-55`)
counts `RecoveryBlocked` as terminal. That single fact disables every recovery
path that already exists:

- `ArtworkRecoveryGate.EnsureRecoveredAsync` returns `AlreadyTerminal` for a
  terminal operation (`src/ArrTags/Artwork/ArtworkRecoveryGate.cs:84-91`), so the
  gate never reconciles it.
- `ArtworkPublisher.ResumeRestorationAsync` requires the state to be
  `RestorePending` (`src/ArrTags/Artwork/ArtworkPublisher.cs:849`), and the catch
  block has just overwritten that with `RestoreBlocked`.
- The one path that would have recovered the subject —
  `ResumeRestorationAsync:892-894`, which reopens a `RecoveryBlocked` operation
  back to `Prepared` — is gated behind exactly the state the catch block
  destroyed.

`OperationCanceledException` at these sites is a **routine** condition, not a
subject defect: a host shutdown, the bounded lifecycle drain
(`ArrTagsLifecycleService.BoundedDrainTimeout`), a per-request timeout, or a
client disconnect. ADR-003 exists precisely so that interrupted image work is
finished on a later run. Converting a cancellation into a terminal pair of
records inverts that intent: the most common cause of interruption produces the
only unrecoverable outcome.

The observed effect on a live host: item `23f05d15d184fa94d6ddf5f56dde6f5c`,
surface `Primary`. The operation record is `Kind: Restoration`, `Phase: 7`
(`RecoveryBlocked`), `Attempt: 0`, `LastError: "The restoration mutation was
cancelled."`, `ObservedAfter: null`, `UpdatedAt 2026-09-24T21:58:55Z`. The state
record is `State: 6` (`RestoreBlocked`) with `SourcePresence: Present` and an
intact, integrity-valid retained source artifact. The badge published earlier
that day (an 11,578,522-byte render) was still the active image, and no trigger
— library event, webhook, post-save, post-scan, or scheduled reconciliation —
could remove it. The only remedy was an out-of-band state edit.

A related consequence is already recorded as accepted limitation `V12-F7-1`: a
subject whose active image is re-adopted by a host refresh enters
`OwnershipLost`, which is blocked for the same structural reason, and v1.2 ships
no in-product recovery trigger. ADR-030 does not change `V12-F7-1`'s accepted
status; it adds the missing in-product remedy (clause 4) so the operator is
never required to hand-edit a durability record.

### Decision

1. **Cancellation leaves a resumable record.** An `OperationCanceledException`
   raised by the image mutation, the item update, or the post-mutation
   verification does **not** write a terminal phase or a blocked state. The
   durable operation is left at its existing lower-bound phase — `MutationStarted`
   or later, whichever was already persisted — and the published state is left at
   `RestorePending` (restoration) or at its pre-mutation resumable phase
   (publication). The existing ADR-003 recovery protocol then resumes the subject
   on the next run.
2. **The lower bound is unchanged.** Each phase is still written *before* its
   external call, and `ArtworkOperationPhases.MayHaveStartedMutation` still
   treats every phase at or after `MutationStarted` as "the mutation may already
   have happened". Recovery re-observes the surface before deciding. This ADR
   changes the *durability* of a cancelled operation, not the fail-safe reading
   of a partial mutation.
3. **Cancellation is not a failure classification.** A cancelled mutation is not
   recorded as a restore failure, does not transition the subject to
   `RestoreBlocked`, and is not counted as a failure in the diagnostics surface.
   It is reported as a cancellation, bounded and secret-free, so an operator can
   distinguish "interrupted" from "refused".
4. **Bounded-retryable failure classification.** A non-cancellation failure of the
   host call is classified by the DG-23 outcome set. The default posture is
   fail-closed: a failure that does not establish that the mutation completed
   leaves the record non-terminal so it is retried under the existing bounded
   retry policy, and only an outcome that establishes the subject cannot be
   recovered may write a terminal phase. `RestoreBlocked` is reserved for that
   terminal class.
5. **In-product re-baseline action.** An administrator-gated action re-baselines
   a subject that a **prior** release already sealed in `OwnershipLost`,
   `OwnershipUnknown`, or `RestoreBlocked`: it discards the stale session record
   for that item and image surface so the next work item observes the current
   surface and captures a fresh recoverable baseline, then the ordinary
   reconciliation re-evaluates the subject. The action is bounded, requires
   administrator elevation, acts on exactly one item and the unindexed `Primary`
   surface, and never mutates an image directly. It is the supported replacement
   for hand-deleting a durability record.
6. The action's preconditions are the existing safety rules: it refuses when a
   non-terminal durable operation exists (the recovery gate owns that case), and
   it never captures a new baseline from an image the plugin cannot currently
   attribute. It is a state-session action, not an image write, so it does not
   weaken ADR-002.
7. No new configuration field is introduced. The action is an administrative
   operation, consistent with ADR-016's decision not to add settings that are not
   needed for normal operation.

### Consequences

- A host restart, drain timeout, or request timeout during a restore or
  publication no longer strands the subject; the next run finishes the work.
- A subject already sealed by v1.2 or earlier becomes recoverable without an
  operator editing `config/ArrTags/authoritative/**` by hand.
- A cancelled mutation can now be retried, so a subject may be observed more than
  once for one interrupted run. The bound is the existing bounded retry policy
  and per-item single-flight; no unbounded loop is introduced because the
  cancellation that triggers the retry is the host's, not ArrTags'.
- The fail-closed guarantee is preserved for the case it exists for: an image
  whose ownership cannot be established is still never mutated automatically.
- No output or render fingerprint changes.

### Rejected alternatives

- **Keep the terminal write and rely on the retry policy.** Rejected: a terminal
  record is never retried, and the state is the gate's authority, not the queue.
- **Write `RestorePending` and a terminal `RecoveryBlocked` operation.** Rejected:
  it leaves the gate skipping the subject (`AlreadyTerminal`) while the state
  looks resumable, which is the same strand with a more misleading record.
- **Delete the durable operation on cancellation.** Rejected: the operation record
  is the ADR-003 fail-safe lower bound; deleting it would discard the evidence
  that a mutation may already have happened.
- **Treat every host-call failure as resumable.** Rejected: an outcome that
  establishes the subject cannot be recovered must stay terminal, or the plugin
  would retry a permanently impossible mutation on every trigger. This is exactly
  what DG-23 decides.
- **Auto-recover `OwnershipLost` on the next run.** Rejected for this ADR: it
  would let ArrTags re-baseline over an image a human or another plugin may have
  set deliberately. Recovery is an explicit administrator action (clause 5).
