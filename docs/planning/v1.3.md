## 2. Goals

### Goal G10 — A cancelled or failed artwork mutation stays resumable

**Value:** An interrupted restore does not permanently strand a poster. The
operation record exists precisely so interrupted image work can be finished on
the next run; a host restart, a bounded drain timeout, or a per-request timeout
must not convert that resumable state into a terminal one.

**Current state:** `ArtworkPublisher` catches `OperationCanceledException` around
the image mutation and writes two **terminal** records before returning
(`src/ArrTags/Artwork/ArtworkPublisher.cs:735-743` for restoration, `:380` and
`:414` for the publication analogues): the durable operation is advanced to
`RecoveryBlocked` and the published state to `RestoreBlocked`. Because
`ArtworkOperationPhases.IsTerminal` includes `RecoveryBlocked`
(`ArtworkOperationPhases.cs:50-55`), the existing resume machinery is then
unreachable: `ArtworkRecoveryGate.EnsureRecoveredAsync` returns `AlreadyTerminal`
for a terminal record (`ArtworkRecoveryGate.cs:84-91`), and
`ArtworkPublisher.ResumeRestorationAsync` requires the state to be
`RestorePending` (`ArtworkPublisher.cs:849`). The one path that could have
recovered the subject — `ResumeRestorationAsync:892-894`, which reopens a
`RecoveryBlocked` operation back to `Prepared` — is gated behind the very state
the catch block overwrote.

Observed on the origin host: item `23f05d15d184fa94d6ddf5f56dde6f5c`, surface
`Primary`. The operation record is `Kind: Restoration`, `Phase: 7`
(`RecoveryBlocked`), `Attempt: 0`, `LastError: "The restoration mutation was
cancelled."`, `ObservedAfter: null`, `UpdatedAt 2026-09-24T21:58:55Z`; the state
record is `State: 6` (`RestoreBlocked`) with `SourcePresence: Present` and an
intact retained source artifact. The badge published earlier that day (an
11,578,522-byte render) was still the active image and could not be removed by
any trigger.

**Decision:** `ADR-030` (Accepted, v1.3). Cancellation is not a terminal outcome.
A cancelled image mutation leaves the durable operation at its existing
lower-bound phase (`MutationStarted`) and the state at `RestorePending`, so the
existing ADR-003 crash-recovery protocol resumes it on the next run. The
bounded-retryable failure classification is decided by DG-23.

**Acceptance criteria:**

- A cancellation raised by the image mutation, the item update, or the
  post-mutation verification leaves the durable operation in a **non-terminal**
  phase and the published state in a resumable phase; the existing recovery gate
  and `ResumeRestorationAsync` resume the subject on the next run without any
  operator action.
- The fail-safe lower-bound rule is preserved: because the phase is written before
  each external call, a cancellation at or after `MutationStarted` leaves the
  record asserting that the mutation may already have happened, and recovery
  re-observes the surface before deciding (ADR-003 is not weakened).
- A cancellation is not counted or classified as a restore failure, and it does
  not transition the subject to `RestoreBlocked`.
- The bounded-retryable and terminal failure classifications are decided by
  DG-23 and covered by tests at the `ArtworkPublisher` boundary, including a
  test that fails against the pre-fix code.
- An in-product re-baseline action is available for a subject already sealed in
  `OwnershipLost`, `OwnershipUnknown`, or `RestoreBlocked` by a **prior** release,
  so an operator is never required to hand-edit a durability record.

### Goal G11 — Bounded artwork outcome observability

**Value:** An operator can tell, without hand-reading state files, why an item
has no badge or why a poster was not corrected.

**Current state:** Two bounded, non-secret reasons are computed and then
discarded.

- `ArtworkRegenerationPlanner.Decide` returns one of six bounded skip reasons
  (`ArtworkRegenerationPlanner.cs:69`, `:74`, `:80`, `:90`, `:110`, `:128`) and
  none of them reaches the log or any counter. A planner `Skip` performs no
  generation attempt, so it also produces no `ArtworkGenerationCompleted` record.
- `ArtworkPublisher.WriteRestoreBlocked` (`:900-912`) writes the terminal
  `RestoreBlocked` state without emitting the bounded reason that caused it.

`DiagnosticsMetrics` counts render **failures** only
(`DiagnosticsMetrics.CreateRenderFailureCounts`, `:168-189`); pass-throughs,
skips, and blocks are not represented, so the ADR-025 clause 3 counter set cannot
distinguish them.

Observed on the origin host: three independent subjects produced no log line and
no counter change — one `OwnershipLost` (a host refresh re-adopted the sidecar,
`V12-F7-1`), one `RestoreBlocked` (G10), and roughly 645 subjects resolving to an
empty badge selection that the configured per-selector allowlist suppressed. The
first two are indistinguishable from a correct no-op; the third is
indistinguishable from a provider failure.

**Decision:** `ADR-031` (Accepted, v1.3), amending ADR-025 clause 3. Emit the
planner skip reason and the restore-block reason in the existing bounded,
secret-free artwork log lines, and extend the diagnostics snapshot with bounded
artwork-outcome counters keyed by a code-owned reason enum.

**Acceptance criteria:**

- Every bounded `ArtworkRegenerationPlanner` skip reason and the bounded
  restore-block reason are emitted at `Information` on the existing artwork log
  line, using the ADR-026 bounded log subject (file name, item-id fallback).
- The diagnostics snapshot gains bounded, process-lifetime artwork-outcome
  counters: regeneration skipped by bounded reason, ownership blocked by bounded
  state, and restore blocked by bounded reason. The snapshot stays fixed-shape,
  bounded, and free of any item identity, item name, path, provider payload,
  credential, or unbounded collection.
- The counters carry a **reason classification only**. A badge value, a quality
  label, a file name, and a path are never placed in the snapshot or a counter
  label, so the ADR-020 clause 4 redaction contract as amended by ADR-026 is
  preserved; the count of selections suppressed by an allowlist is exposed as a
  count, not as the suppressed values.
- The emission is bounded by the existing `LogThrottle` and does not add an
  unbounded log or counter surface; the settings-page panel is updated to render
  the new counters and keeps its fail-closed behavior.
- The endpoint and the extended counter set are security-reviewed.

### Goal G12 — Restoration verification semantics

**Value:** A restore is not sealed as permanently blocked because the host
returned a visually correct but byte-different image.

**Current state:** After writing the retained baseline back, the publisher
requires Jellyfin's readback to hash **exactly** to the retained artifact
(`ArtworkPublisher.MatchesRestorationCandidate`, `:936-946`; the expected value
is `state.SourceArtifactId`, set at `:659`). A mismatch is fail-closed and
terminal (`WriteRestoreBlocked`, `:818-819`). Whether the pinned host's
`SaveImage` → read-back path returns byte-identical bytes is **not verified**; it
is inherited as an unexamined assumption from the publication path, where the
same style of comparison is used and where 650+ subjects have passed.

This is recorded as a **decision to be settled**, not as a defect: the origin
session observed the cancellation path (G10), not a byte-mismatch path, so no
limitation is registered for it. If DG-25 establishes that the host normalizes
image bytes, a new open limitation is registered at that point.

**Decision:** `ADR-032` (Accepted, v1.3), subject to a `jellyfin-expert`
verification spike. Restoration verification accepts a readback that is
byte-identical **or** that is confirmed equivalent under a documented,
content-derived equivalence rule, and remains fail-closed otherwise. DG-25
selects the rule.

**Acceptance criteria:**

- A `jellyfin-expert` spike records, against the pinned Jellyfin 12 host, whether
  `IProviderManager.SaveImage` followed by the ArrTags image read-back returns
  byte-identical bytes for a JPEG and a PNG source, and what the host's image
  normalization (if any) does to them.
- The restoration verification predicate is derived from the spike result: if the
  host is byte-preserving, the predicate stays content-SHA-exact and the spike
  result is recorded as the evidence that closes the question; if it is not, the
  predicate adopts a documented content-derived equivalence rule that cannot
  accept a visually different image.
- The predicate remains fail-closed: an unobservable readback, a presence
  mismatch, and an image that fails the equivalence rule all remain non-mutating
  and are classified, not silently accepted.
- A regression test covers the equivalence rule at the `ArtworkPublisher`
  boundary, including a negative case that must still block.

## 5. Dependency order

As amended on 2026-10-02 (user-approved), the authoritative v1.3 phase execution
order is **26, 22, 23, 24, 25**. Phase number no longer equals order; this section
is authoritative for the order of v1.3's phases, and each phase's own
`Authoritative Phase N execution order` remains authoritative for the order of its
tasks. The product dependency order below is unchanged; Phase 26 precedes it and
depends on none of it.

1. **Phase 26 - Harness and agent-contract remediation** first. It is internal-only
   harness maintenance, with no goal, no decision gate, and no ADR. It corrects the
   agent-process failures recorded in the v1.2 advisory reviews, which cost that
   release two full artifact/live/security re-derivation cycles; the harness must be
   in place before v1.3's product phases and its build/live/security/release cycle
   run under it.
2. **Goal G10 (ADR-030)** next. It is the highest-severity defect, it leaves
   media in a state the plugin itself caused and cannot undo, and it is the
   smallest change.
3. **Goal G11 (ADR-031)** next. It is what makes the G10 behavior observable, both
   in tests and on the pinned host, and logging is cross-cutting: it amends the
   ADR-025 contract and edits artwork log lines.
4. **Goal G12 (ADR-032)** next. It is an independent restoration-path predicate
   and is gated on its own verification spike.
5. **Release (version bump, build/package, live verification, release security
   review, release review)** last.

## 9. Verification requirements

- Unit/integration tests for each task, including: a cancelled restoration
  mutation leaving a non-terminal operation and a resumable state; a cancelled
  publication mutation and item update behaving the same way; the in-product
  re-baseline action recovering a synthetic `OwnershipLost`/`RestoreBlocked`
  subject; every `Decide` skip reason reaching the log and its counter; the
  snapshot staying fixed-shape and value-free; and the restoration equivalence
  rule including its negative case.
- Each regression test for G10 and G12 must fail against the pre-fix code, and
  the pre-fix behavior is recorded in the worker report as the reproduced defect.
- A `security-reviewer` pass over the extended diagnostics endpoint (G11) and the
  new in-product action (G10), confirming no secret, path, item name, or
  unbounded collection is exposed and that the action is administrator-gated.
- Live verification on the pinned Jellyfin `12.0.0` host: interrupt a restore
  with a host restart and prove the subject resumes without operator action; run
  the in-product re-baseline action against a subject sealed in `RestoreBlocked`;
  and confirm the new counters move for a suppressed selection and a skipped
  regeneration.
- Reproducible build/package at the v1.3 version (`1.3.0.0`).

## 10. Out of scope

- **F5** (the renderer depends on a host-supplied SkiaSharp with no bundled
  fallback) remains **Accepted** and is not implemented by v1.3.
- **V12-F7-1** remains an accepted historical record; v1.3 provides a remedy for
  it but does not rewrite its text or change its accepted status retroactively.
- Badge selection semantics, the per-selector allowlist (ADR-017), badge
  geometry/placement/size (ADR-019, ADR-027), rendering output, the render
  fingerprint, the provider inventory cache (ADR-018), and reconciliation coverage
  (ADR-022) are unchanged. v1.3 makes a suppressed selection **countable**; it
  does not change what is selected.
- All V1 deliberate exclusions in `GOALS.md` and `docs/limitations/` (Jellyfin
  versions before 12, modifying media files, Arr write operations, non-poster
  artwork, user-specific badges, unapproved services, path fallback) remain out
  of scope.
- Additional metadata providers, series/season-level badges, alternative artwork
  types, and additional media-management applications remain outside the accepted
  scope.
