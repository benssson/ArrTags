# Changelog - 1.2.0

## Phase 15 - Plugin log subject identifier and render classification (v1.2)

### Task 15.1 - Bounded log-subject policy and helper

**Status:** Complete. Owns ADR-026 clauses 1-2 (G9); the clause 3 threading is
task 15.2.

`src/ArrTags/Logging/LogSubject.cs` is the shared bounded log-subject helper.
`LogSubject.Create(Guid jellyfinItemId, string? primaryPath)` returns the
file-name component only (`Path.GetFileName`), never a directory, drive, share,
or parent path, and falls back to the Jellyfin item identifier in `D` format
whenever no usable name is available; `LogSubject.Create(Guid jellyfinItemId)`
is the item-id-only overload for the explicit fallback sites. The file name is
bounded to the documented `LogSubject.MaximumScalarValues` (128 Unicode scalar
values), has control scalars removed, and is otherwise emitted verbatim
(whitespace is not collapsed or trimmed), all in a single scalar-wise pass so a
surrogate pair is never split. An empty, whitespace, or control-only name — and
a name that reduces to whitespace-only text after normalization, for example
`" \u0001 "` — falls back to the item identifier. The helper never throws for a
null, empty, whitespace, or otherwise unusable path.

`tests/ArrTags.Tests/LogSubjectTests.cs` adds 23 cases covering the
file-name-only subject (directory segments never appear in the result), the
documented bound (exactly-at-bound unchanged, over-bound truncated, a surrogate
pair is never split), control-scalar removal (C0/C1, DEL, CR/LF, tab) without
whitespace collapsing, non-ASCII and combining text emitted verbatim,
empty/whitespace and control-reduced fallback, and the `D`-format
item-identifier fallback. Test sensitivity was probed by temporarily removing
each behaviour (path splitting, the scalar bound, control removal, the
post-normalization fallback check, and the `D` fallback format): the
corresponding cases failed and every probe was reverted.

`./build.sh build` reported 0 warnings / 0 errors; the default suite is Failed 0,
Passed 1517, Skipped 63, Total 1580 (pre-task baseline Failed 0, Passed 1494,
Skipped 63, Total 1557; +23 passed / +23 total, 0 new skips).

Task 15.1 adds the helper and policy only. Threading it through the
identity-bearing and fallback sites is task 15.2, the render classification is
task 15.3, and the ADR-020 clause 4 amendment, canonical documentation, and
logging security review are task 15.4; limitation F8 remains open until Phase 15
completes.

### Task 15.2 - Thread the bounded log subject through the identity-bearing and fallback sites

**Status:** Complete. Owns ADR-026 clause 3 (G9); the render classification is
task 15.3 and the ADR-020 amendment, canonical documentation, security review,
and F8 resolution are task 15.4.

The bounded `LogSubject` is now threaded through every item-id-emitting site
ADR-026 clause 3 names. The identity-bearing sites pass the primary path when
one is available and use the helper for the item-id fallback:

- `ArtworkGenerationCoordinator.LogOutcome` uses
  `LogSubject.Create(request.JellyfinItemId, request.MediaIdentity.MediaLocation?.PrimaryPath)`.
- `MetadataReconciliationProcessor`'s two provider-error metadata-read-failure
  paths (the reader-threw catch and the failed-read result) use the identity
  created by `MediaIdentityFactory.TryCreate`.
- `RadarrMetadataReader.LogMatch` and `SonarrMetadataReader.LogMatch` use
  `identity.MediaLocation?.PrimaryPath`.

The mixed `MetadataReconciliationProcessor.Discard` site gains a
`Discard(Guid itemId, string? primaryPath, string reason)` overload: the
two-argument overload (used where no identity exists: version mismatch, item
missing before resolve, identity-creation failure, ineligibility, or no
connection) passes no path, and the six changed-basis discards after identity
creation pass `identity.MediaLocation?.PrimaryPath`. No path is invented where
none exists. The fallback sites emit the item identifier explicitly:
`LibraryWorkWorker` uses `LogSubject.Create(item.Key.ItemId)` as the subject of
the processed and retry-scheduled records and retains the existing bounded
connection scope and image surface alongside it as
`<subject> (<connection|*>, <surface>)`; ADR-026 clause 1 replaces the emitted
item identifier only, and the connection identity and surface are allowed,
non-secret diagnostics (ADR-020 clause 4). `ArrTagsLifecycleService` logs
`LogSubject.Create(e.ItemId)` for the item-removed event. The sites ADR-026
clause 3 marks unchanged (`ConcurrencyLimitedArrMetadataReader`,
`WebhookIntakeService`, `WebhookAuthenticationFilter`,
`LibraryReconciliationService`) are not touched.

`tests/ArrTags.Tests/LogRedactionTests.cs` adds 13 per-site theories over the
six verbosity levels (78 cases): the artwork site, both metadata-read-failure
paths (the reader-threw catch and the failed-read result), and the Sonarr/Radarr
match sites emit the file-name component only with no path separator and no item
identifier; the mixed discard site emits the file name when a path is available
(post-identity discard), falls back to the item id when the identity has no
usable path, and falls back when no identity exists (the pre-resolve version
mismatch); the worker's processed and scheduled-retry records emit the item-id
fallback with the retained connection/surface context; and the lifecycle-removal
site emits the item-id fallback. Each discard case pins the exact discard branch
it drives, each read-failure case pins the path it drives (reader-threw catch or
failed-read result), and the retry case pins the `WorkItemRetryScheduled`
record. Every case asserts the captured records carry no sentinel.

Test sensitivity was probed by temporarily reverting the subject substitution
per site and re-running the class. Reverting the identity-bearing substitutions
to the item id failed the artwork (3 cases at Information and above), the
failed-read (4 at Warning and above) and reader-threw (4 at Warning and above)
read-failure paths, Radarr (2 at Debug and above), and Sonarr (2 at Debug and
above) file-name theories; ignoring the discard path failed the mixed path
theory (3); reverting the worker context to the pre-task `WorkItemKey` text
failed the processed (2 at Debug and above) and scheduled-retry (2) theories;
replacing the fallback with a non-item-id subject failed the failed-read
fallback (4), the reader-threw fallback (4), the discard identity-without-path
(3), and the discard no-identity (3) theories; dropping the retained
connection/surface context failed the processed (2) and retry (2) context
assertions; and emitting an `N`-format identifier at the lifecycle removal site
failed its theory (2). The two probe rounds reported 22 and 20 failures
respectively; every probe was reverted and the final `LogRedactionTests` run
reports 143 passed.

The lifecycle-removal site emitted the `D`-format item identifier before this
task and emits the same bounded fallback now, so its output is unchanged; the
change there is the explicit shared-helper threading. The worker records change
from the `WorkItemKey(<id:N>, <connection>, <surface>)` text to the item-id-only
subject followed by the retained connection scope and surface.

ADR-026 clause 3's parenthetical classes the ineligible and
connection-unavailable pre-publish discards as sites where no identity exists;
in the code those discards run after identity creation and a path is available.
The implementation follows the clause 3 enumeration and threads no path there;
reconciling the ADR wording with the actual call sites is deferred to task 15.4.
